RELAY — the autonomous dispatch desk

Solution overview for the engineering manager · MERN + TypeScript
95 automated tests · strict TypeScript · runs with npm install && npm run dev

1 Problem → solution

Problem. Dispatchers juggle availability, phone calls and spreadsheets. When a rider doesn’t answer or nobody fits, orders sit idle — and nobody notices until a customer complains.
  • Recommend eligible riders with an explained ranking.
  • Reserve rider capacity the moment someone is assigned; release it on any failure.
  • Auto-escalate: no confirmation in 2 h (configurable) → job lands in the Manual Queue, with the reason on record.
  • Surface what needs a human on one dashboard; audit every action.

2 Dispatcher’s primary workflow

Job created›Ranked riders + “why”›Assign / override (reason)›Rider confirms›Picked up → Delivered
No answer in 2 h›Manual queue›Investigate›Reassign›Done

  • Job page: lifecycle stepper, countdown ring, full activity timeline, every failed attempt kept.
  • Riders page: capacity ledger + “can they take another delivery?” check.

3 Recommendations & automatic queue handling

  • Each candidate shows per-factor points and a sentence: “Recommended over Rahul: 9.4 pts higher, mainly closer to pickup.”
  • Picking anyone but #1 requires a reason; both riders & scores are logged.
  • Nobody eligible → job stays unassigned, is flagged once, appears in “Needs attention”.
  • Timeout (sweeper + lazy check on accept + orphan repair): attempt → EXPIRED (kept), capacity released, job → Manual Queue, immediately re-assignable. Reject / withdraw take the same path.
  • Reviewer can set the window to 0.5 min or advance a simulated clock — no 2-hour wait.

! One important trade-off

Compare-and-set instead of transactions. I made every write a single-document CAS (job status+pointer, assignment status, guarded capacity $inc) and order steps so a crash leaves something detectable, instead of requiring a MongoDB replica set.
  • Gain: runs on any mongod (even in-memory), races resolved and covered by tests: accept-vs-timeout, two dispatchers, over-commit.
  • Cost: a crash between a state change and its audit event could drop an event; mitigated by an integrity check + orphan repair, fixed properly by transactions/outbox next.

4 Architecture & data model

  • Job ≠ assignment: a job accumulates attempts (timed-out, rejected, reassigned) that are never deleted.
  • Rider ledger: reserved vs active load, changed only by whoever wins the assignment CAS → released exactly once.
  • History: separate append-only event log (type, time, actor, details) — status never used to rebuild the past.
  • Indexes: {status, priority, createdAt} queues · {status, expiresAt} sweeper · {jobId,_id} history.
